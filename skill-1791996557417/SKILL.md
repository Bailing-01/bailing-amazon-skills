name: 亚马逊周度五维复盘
description: 每周一或用户说「周复盘/周报/五维复盘」时使用：按周对比各店铺单品的销量、访客、转化率、访问深度、售价，定位问题在流量端还是 Listing 端。
---
# 数据
1. 优先从 ERP 连接器（如领星 MCP：help → search → action）拉上周（周六至周五）与前 3 周按子 ASIN 的：销量、销售额、Sessions、页面浏览量、转化率、平均售价、广告花费。没有连接器时，让用户上传后台业务报告周 CSV（文件名带周期，例 Y26W34）。
2. 子 ASIN 按内部 SKU/父体归类；未归类的单独列出。缺失值标「无数据」，不编造。

# 分析
1. 派生：访问深度 = 页面浏览量 ÷ Sessions；7 天平均 = 周销量 ÷ 7；访客环比 = 本周 Sessions − 上周 Sessions。
2. 看趋势不看单点：用连续 3–4 周方向判断，单周波动不下结论。
3. 五维归因（销量 = 访客 × 转化率）：
   - 访客稳、转化降 → Listing 端（价格、评分/差评、页面改动、库存/配送时效）。
   - 访客降、转化稳 → 流量端（广告预算/出价、关键词排名、季节性）。
   - 两者都降 → 先查库存、Buy Box、Listing 被改或被压制。
4. 价格对账：售价曲线与销量叠看，降价后销量无起色则不再降价。
5. 列访客前 5 的子 ASIN（谁在扛量）和环比跌幅最大的 3 个。

# 输出
- 每店一张表：SKU / 销量 / 访客 / 转化率 / 访问深度 / 售价 / 广告花费，各带周环比。
- 3–5 条结论：问题在流量端还是 Listing 端，以及本周建议动作。广告调整走广告优化技能，只出建议，写操作先经用户确认。
- 月末另做当月归档汇总（可导出 Excel）。
