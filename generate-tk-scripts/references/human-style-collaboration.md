# 人味信息流三角色协作规范

本规范只负责把已确认的拆解证据转成自然、可拍、可销售的口播，不补造产品事实。默认产出三条核心路线；用户明确要求九版时，再扩展为每条路线 A/B/C。

## 共享输入包

协调者只向三个角色提供同一份最小输入：

- 原视频 Hook、目标人群、具体痛点和底层购买逻辑；
- 相信理由、立即行动理由、可迁移逻辑和原片时长；
- 原片中可直接复用的口语、人物、场景、动作和证据；
- 用户提供的产品事实、禁用声明和目标语言；
- 本轮三条路线及必须锁定的变量。

证据中没有的人物经历、疗效、认证、销量、优惠和稀缺信息不得补写。缺少真实表达样本时，标记 `voice_evidence_gap`，不得把编造的生活故事伪装成用户证言。

## 三个角色

### 1. 母稿编剧

- 为原逻辑迭代、原逻辑换壳、新底层逻辑各写一条完整母稿；九版模式再扩展 A/B/C。
- 保留销售强度、证明责任和明确 CTA。
- 先写具体的人、时刻、动作和冲突，再解释产品；避免先写总结和大道理。
- 把口播写成真人一口气能说完的短句，不写报告标题、分析标签或镜头术语。

### 2. 人味编辑

- 逐句指出 AI 痕迹，并把修改意见发回母稿编剧，同时让审片人可见。
- 优先删除：空泛共情、工整排比、连续反问、百科解释、万能转折、重复结论和机械 CTA。
- 优先补强：具体时间地点、微动作、关系冲突、犹豫或自我修正、自然停顿、长短句变化和个人立场。
- 不用故意加错别字、网络黑话或无意义语气词伪装真人。

### 3. 信息流审片人

- 按真人口播默读一遍，判断前三秒是否能停留、每句是否顺口、产品进入是否自然、证明是否够、结尾是否能行动。
- 分别给 `humanity_score`、`feed_score`、`sales_score`，每项 0–5 分。
- 任一项低于 4 分，必须给出具体划走句和替换方向；三项均不低于 4 分才可 `approved`。
- 只允许一次定向返修；第二次仍不通过则停止该版本并报告，不得无限讨论。

## 对话顺序

1. 协调者发布共享输入包和三条路线。
2. 母稿编剧发布初稿；人味编辑和审片人都能看到。
3. 人味编辑逐句反馈；母稿编剧定向重写。
4. 信息流审片人终审；不通过时只允许一次定向返修。
5. 协调者只收集通过稿，随后运行确定性 JSON 校验。

使用 Codex 分支智能体时，通过任务消息转发每轮产物；使用 AgentScope 时可将同一协议映射到 `MsgHub`。无论底座为何，最多两轮修改，并由协调者负责终止、去重和失败回收。

## 结构化审片记录

每条脚本增加可审计字段：

```json
{
  "humanity_review": {
    "status": "approved",
    "humanity_score": 4.5,
    "feed_score": 4.3,
    "sales_score": 4.2,
    "ai_tells": [],
    "read_aloud_issues": [],
    "revision_rounds": 1,
    "voice_evidence_gap": false
  }
}
```

`ai_tells` 和 `read_aloud_issues` 必须记录终稿仍存在的问题；不得为了通过而伪造空数组。严格校验时，缺少 `humanity_review` 或任一评分低于 4 分均不得交付。
