ASIN Listing 风险监控
怎么用？有什么用？

给亚马逊卖家 / 运营的本地风控脚手架：盯关键词、广告、负评、违禁词、跨站点，缺数据就标「无数据」，不编造。

一句话

它帮你把「这个 ASIN 今天安不安全」拆成 5 个可勾选项，落成表格和短结论；Skill 负责检查流程，本机文件夹负责记账看板。

有什么用？

防漏检每天按固定五项扫，不会只看销量忘了违禁词或跨站传染。
可复盘CSV + 报告可对比昨天，负评暴增、广告突然停投看得见。
可分享骨架可公开；真实店铺数据留在本机私有备份，不混进 GitHub。
可协作朋友 clone 仓库就能开工；有 Grok Bot 还能装同名 Skill 自动跑流程。
适合：美亚白牌美妆/护肤、代运营可逆品（如 bidet seat）等需要盯 Listing 政策与账号健康的人。不适合：指望它自动登录广告后台代你点投放——没有 Seller Central 权限时，广告花费一律「无数据」。

两件套分别干什么？

东西是什么新手怎么理解
asin-risk-monitor/
本地骨架		 CSV 表、词库、Python 小脚本、index.html 看板 你的「账本 + 仪表盘」。填数、看表、扫违禁词都在这里。
asin-listing-risk-monitor
Skill		 给 AI 助手的检查步骤说明书 你的「检查清单」。跟 Bot 说扫某个 ASIN，它按 7 步跑并出短结论。

五项检查分别管什么？

  1. 关键词可搜索性：核心词搜得到吗？有机大概第几？结果卡有没有 Sponsored？
  2. 广告是否在投放：有 Ads 后台就记状态/花费；没有就标「无数据」，别瞎猜。
  3. 负评日均（昨今对比）：1★/2★ 与昨日差多少；没有昨日快照就「无数据」。
  4. 违禁词扫描：标题/五点/A+ 对词库（义成/冒器/药品/其他）；命中=人工复核线索，≠最终违规定论。
  5. 跨站点：US/CA/MX/UK/DE/FR 文案或可用性变动是否可能影响美站或互相传染。

新手 10 分钟上手

  1. 拿到骨架
    git clone https://github.com/Bailing-01/bailing-amazon-skills.git
    把里面的 asin-risk-monitor/ 拷到本机，例如 ~/Documents/asin-risk-monitor/。
  2. 登记你的 ASIN
    打开 config/asins.csv，填：店铺、站点、ASIN、核心关键词（多个用 | 分隔）。至少 1 个 ASIN 就能开始。
  3. 跑第一天检查
    有 Grok Bot / 已装 Skill：把 ASIN 或 Listing 链接发给「ASIN风控」类助手，让它按五项抓公页并回写 daily/。
    没有 Bot：自己打开亚马逊公页 / Seller Central，把能核实的数字抄进 daily/ 五张表，来源写在 source 列。
  4. 违禁词（可选但推荐）
    把标题+五点+A+ 存成 listing.txt，在骨架目录执行：
    python3 scripts/scan_forbidden.py listing.txt
  5. 看表 + 写结论
    浏览器打开 index.html → 选择 daily/ 里的 CSV（不上传）。再按 templates/daily_report.md 写短结论和行动项。
铁规则：缺数据就写「无数据」。不要猜排名、花费、曝光、点击、评论数。宁可空着，也不要假数误报锁店风险。

每天怎么用（建议节奏）

  1. 对重点 ASIN 复扫五项（或让 Bot 复扫）。
  2. 把结果追加进 daily/（同一天可覆盖，跨天请保留历史或另存快照）。
  3. 用 scripts/diff_neg_reviews.py 对比昨日负评 CSV，算 delta。
  4. 只把「结论 + 行动项」发群；原始 CSV 留本机。

常见坑

  • 搜不到 Sponsored ≠ 广告关了：公页徽章只是旁证，花费仍以 Ads 后台为准。
  • 词库命中 ≠ 立刻违规：比如 OTC 文案里的 without a prescription，要人工结合类目语境。
  • CA/MX 同 ASIN 404：可能根本没开同 ASIN，别当成「被删」恐慌；EU 常被反爬，标题可能「无数据」。
  • 别把真实店铺扫描推上 Public 仓库：GitHub 上只放空表头骨架；实扫放本机私有备份。
本介绍页不存储、不联网上传你的 CSV。看板 index.html 同样只在本地读你选中的文件。
